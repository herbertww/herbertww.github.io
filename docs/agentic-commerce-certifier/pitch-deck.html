The Idea4 minDemo
The solution, step by step

Scan the money leg. Certify it. Keep it fixed.

01 — Scan

A headless agent buys something

An eight-way signature challenge, a real checkout session, delegated-token authorisation, mandate-scope negatives, refund, dispute evidence. Sandbox only, test mode, compensating void on every auth.

02 — Certify

~120 checks, five pillars, one score

Deterministic and evidence-backed. A 90-day W3C Verifiable Credential, published to a public registry, revoked in minutes when a weekly re-run regresses.

03 — Remediate

Failures come back as fixes

A pull request through a GitHub App carrying the check ID, evidence link, patch and a reproducing test — plus a CI gate, so readiness can't silently rot.

Five concepts, four domains. Agentic commerce — conformance to UCP, ACP, AP2, Agent Pay, Visa TAP. Payments foundations — the rubric follows the transaction's anatomy, and the score is priced into the fee stack. Data-driven finance — telemetry becomes a risk signal sold to issuers, and certification is deliberately rule-based so ML can never hard-fail a merchant. Platforms & infrastructure — a registry agents read, a portfolio PSPs resell. PayFi — x402 and PayNow request-to-pay as alternate rails.

How it's built — a run is a transaction saga, not a crawl

Control plane

Tenant, contract, credential

  • Next.js 15 · Hono/TypeScript
  • Temporal orchestration
  • Credential signed in a KMS HSM
  • Edge registry + revocation list
Probe plane

The only thing touching merchants

  • Ephemeral single-use Fargate task
  • Playwright + raw undici for byte-exact signatures
  • Claude journey agent, MCP client
  • Published egress IPs, no long-lived secrets
Scoring plane

Deterministic, replayable

  • Rules-as-code, versioned
  • LLM advisory only, weight 0
  • Evidence → S3 Object Lock
  • ClickHouse benchmarks
merchant ▸ probe ▸ immutable evidence ▸ scoring ▸ credential ▸ registry ▸ agents · PSPs · issuers

L0–L1 are free and are the whole top of funnel. L3 — the money leg — needs a contract, a sandbox and a PSP relationship, which is exactly why every free scanner stops at L1. Marginal cost of a full run: S$0.70. Never touches a PAN; test mode enforced before the first request and on every auth response.

Why a network buys this

Verifiable Intent assumes the merchant side holds. Nothing observes whether it does.

It changes fraud scoring, liability assignment and chargeback procedure — but only if the merchant integration actually enforces the mandate, and the demo you just watched shows one that doesn't. A registered merchant approving over-cap tokens is a liability carried blind. We sell a per-inquiry readiness signal with stable reason codes — GL-P4-02-OVERCAP, GL-P2-10-BLOCKED — machine-actionable at authorisation, in the shape a network already sells VAS. It makes the liability framework enforceable rather than aspirational.

Feasibility2 min
Regulatory, technical and partner realities

We are a testing and assurance service. That is a licence decision, not an accident.

Regulatory

No MAS licence required, by design

MAS created no separate category for AI-initiated payments — existing consumer protection, AML and KYC apply, and the agent is an extension of the account holder. We hold no funds and move no real money, so no PS Act licence. PDPA residency in ap-southeast-1; SOC 2 Type II before the first FI contract.

Anchor

SAFR turns a white paper into a line item

Pillar P5 scores the merchant's audit envelope against SAFR's four pillars — policy-bound execution, real-time validation, auditability, interoperability. Measurable, not just briefed on.

Legal

Assurance, not indemnity

The credential asserts observed behaviour of a named domain under a named rubric version at a timestamp — explicitly not a warranty. Backed by professional indemnity cover before the first paid certificate.
